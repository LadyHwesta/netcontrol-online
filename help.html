2026-09-01 — Optional Redis Support for Running with Multiple Workers (v2.26.0)
  • Deploy/ops change, not an in-app feature: an instance can now safely run more than one uvicorn worker process (WORKERS in .env, default 1, unchanged). Previously the rate limiter and the DMR/APRS relay-push caches each held their own state in memory, private to whichever single worker happened to handle a given request — harmless with one worker, but with more than one the rate limiter silently multiplied every configured limit by the worker count, and the relay caches could serve stale data to whichever worker didn't get the latest push.
  • Setting REDIS_URL gives both a shared backing store instead, correct across every worker. Entirely optional and additive — unset (the default), nothing changes. See "Running with multiple workers" in README.md.

QUICK START

1. Create a Net under My Nets — give it a name and frequency.

2. Open the net and click ▶ Start New Session to begin.

3. Use the Check-In form or Expected Stations list to log stations as they call in.

4. Click ■ End Session when the net closes — a session summary card will appear automatically.

Keyboard shortcut: Press / anywhere on the session page to instantly focus the callsign input.

ORGANIZATIONS

Every account belongs to at least one Organization — nets, sessions, and check-ins are scoped to it, so two organizations sharing the same install never see each other's nets. When registering, choose Create new (enter a name and website URL — you become its admin, pending a Super Admin's approval) or Join existing (that organization's own admin must approve you). Either way you can't log in until approved.

Belong to more than one organization? A switcher appears next to your callsign in the header — pick which one you're working as, and the net list updates to match. To join an additional organization later, ask its admin how to request access.

An organization's admin can approve or reject pending members from a scoped view of the Admin page — separate from, and smaller than, the site-wide Super Admin role, which can still see and manage everything across every organization.

SESSION CLOCK & TIMER

While a session is live, a clock bar appears showing local time, UTC time, and the elapsed session time. The timer starts from when the session was opened and updates every second.

The clock disappears automatically when the session ends.

CALLSIGN LOOKUP & SEARCH

Full callsign (e.g. W7KOL) — type it in and the system looks up the licensee name, class, state, and grid from the FCC database, auto-filling the Name field.

Suffix search (e.g. KOL) — type letters without a district number and the system searches your net's check-in history for matching callsigns. A dropdown appears sorted by suffix. Click any result to select it and trigger a full FCC lookup.

Suffix search only finds callsigns already in your net's history. For a brand-new station, type their full callsign.

STATION REMARKS

After looking up a callsign, a small 📝 Remark pill appears in the lookup info bar. Click it to add or edit a persistent note about that station (e.g. "portable op", "relay to W7NET", "hearing impaired — use Winlink").

Remarks are saved per net and appear every time that station is looked up during any future session on that net.

MANUAL CHECK-IN FORM

Fill in callsign, name (auto-filled from FCC), signal report, and optional comments. Check Has Traffic before clicking Check In or pressing Enter.

Duplicate callsigns in the same session are automatically rejected.

BULK IMPORT FROM CSV

Click ⬆ Import CSV in a session's toolbar (next to ⬇ CSV export) to add a whole roster at once instead of typing each check-in in by hand — built mainly for 🕐 Log Past Net, where you're often re-entering a full paper roster after the fact, but it works on any session that can still take check-ins, live ones included.

The dialog has a Download a sample CSV link showing the exact columns expected. Only Callsign is required; Name, Signal Report, Comments, Has Traffic, Evac Zone, and the two DMR fields are all optional and matched case-insensitively, so your own column headers don't need to match exactly.

Each row is validated independently — a bad row (a missing callsign, a duplicate) is reported and skipped without blocking the rest of the import.

GMRS NETS

When creating a net, select GMRS as the net type. GMRS nets behave like ham nets with a few differences:

Shared callsigns — a GMRS licence covers an entire family. The same callsign can check in multiple times in a single session. Use the Name field to identify each individual operator (e.g. "Dad", "Mom", "Mobile 1").

Callsign lookup — GMRS callsigns (format: 3–4 letters followed by 3–4 digits, e.g. WSMC512) are looked up in a local copy of the FCC ULS GMRS database. The database is refreshed daily; new licences may take up to 24 hours to appear.

ARES mode, the Digital Voice integration, and the APRS station map are not available for GMRS nets and are hidden automatically.

EXPECTED STATIONS

Click Expected Stations to expand the panel. Set the minimum check-in count and lookback window (weeks), then click Load List.

Each row shows two checkboxes: Check In to log them immediately, and Traffic to pre-flag traffic before they're formally logged. On ARES nets, a 📍 zone badge shows their last known evacuation zone.

Already-checked-in stations are greyed out and the list refreshes automatically.

TRAFFIC MANAGEMENT

When any station has traffic, a red 📢 TRAFFIC banner appears listing them as interactive chips. Once you've called a station to pass their traffic, tick the checkbox on their chip — it strikes through and dims to show it's been handled. Unchecked chips remain prominent so nothing gets missed.

Pre-flagged stations from Expected Stations appear with a ⏳ badge until formally checked in. Their checkbox is disabled until they call in.

In the check-ins table, click the 📢 / ○ button in the Traffic column to toggle the flag on any station.

TRAFFIC MESSAGE LOG

Click 📋 TRAFFIC MESSAGE LOG to expand the panel. Use it to record individual traffic messages handled during the session — message number, origin, destination, type (Formal / Informal / Health & Welfare), and notes.

The Status dropdown on each row lets you track progress: Received → Relayed → Delivered (or Undeliverable). Changes save immediately.

The message log is included in the ICS-205 export.

NET CONTROL SCRIPT

Net owners can attach a script to a net from its Edit form, on its own 📜 Net Script tab (separate from the Details tab holding name/type/frequency/etc.). The left side has a formatting toolbar (Bold, Italic, headings, list, rule — click instead of remembering the syntax), the editor itself (which grows as you type to fit what you've written), and a live Preview below it that renders exactly what the script will look like — using placeholder sample names, since there's no live session to pull real values from while editing. A collapsible 🔤 Insert a Variable reference floats on the right — click any {{variable}} to insert it at the cursor — and stays in view as you scroll through a long script instead of scrolling away.

When set, a collapsible 📜 NET SCRIPT panel is pinned to the top of the live check-in screen, open by default, so you can read from it without a second window or a printed sheet — even while scrolling through check-ins.

MARKUP

A small, deliberately limited set of formatting is supported: **bold**, *italic*, # / ## / ### heading, - item bullet lists, and --- / === as a horizontal rule (alone on its own line). Everything else — blank lines, indentation, plain text — renders exactly as typed; this is not full Markdown or HTML, so unrecognized syntax (including literal </>) always shows as plain text rather than being interpreted.

VARIABLES

{{variable}} placeholders are filled in with live session info wherever the script is shown:

{{net_name}}The net's name
{{net_control}}Net Control name — callsign
{{net_control_callsign}} / {{net_control_name}}Just the callsign / just the name
{{broadcaster}}Broadcaster name — callsign (Additional Broadcast nets only)
{{broadcaster_callsign}} / {{broadcaster_name}}Just the callsign / just the name
{{broadcast_label}}The net's custom broadcast name (e.g. "Amateur Radio Newsline")
{{net_control_next}}Next week's Net Control name — callsign
{{net_control_next_callsign}} / {{net_control_next_name}}Just the callsign / just the name
{{broadcaster_next}}Next week's Broadcaster name — callsign
{{broadcaster_next_callsign}} / {{broadcaster_next_name}}Just the callsign / just the name

Net Control falls back to whoever started the session if no one signed up on the Schedule tab for that date; Broadcaster only fills in from a Schedule sign-up. The _next variables look one week ahead and are never filled by fallback — they stay blank until someone actually signs up on the Schedule tab for that date. An unrecognized {{...}} is left as-is rather than silently dropped, so a typo is easy to spot. For example:

# Monday Night Net Script

Good evening, this is **{{net_control}}**, your net control operator
for the {{net_name}}.

Coming up: tonight's {{broadcast_label}} segment, read by {{broadcaster}}.

- If you would like to check in, please call now with your callsign.
- Traffic? Let us know when you check in.

---

Next week's net control will be {{net_control_next}}.

Thank you all for checking in. This net is now closed.

Leave the field blank to hide the panel entirely. Click the panel header any time to collapse or reopen it during a session.

NET SHARING

Net owners can share a net with other registered operators. Open the net's Edit form and expand the 🔗 Sharing section at the bottom.

Choose Share with all registered users to give every active account access, or select individual users from the list. Click Save Sharing to apply — this is separate from the main Save button.

Shared nets appear in other operators' net lists with a Shared badge and show the owner's callsign. Shared users can start sessions and add check-ins, but cannot edit the net configuration or manage sharing.

Admins can see and open all nets on the system regardless of sharing settings.

SCHEDULING

In the Schedule tab of a net, add weekly repeating time slots (day, time, timezone). These appear as a calendar of upcoming dates.

The Timezone field auto-fills to your browser's detected timezone when you open the form, and autocompletes from the full IANA timezone list — you're rarely typing it from scratch. It only affects entry, though: change it if the net actually runs somewhere else.

Every schedule time shown anywhere — the Schedule tab, the Upcoming list, and the public /directory page — includes a (H:MM your time) conversion whenever your browser's timezone differs from the one the schedule was declared in, so you don't have to do the math yourself.

Operators can click Sign Up next to any future date to claim the Net Control slot. The net owner can instead click 👤 Assign to put a registered operator on the schedule.

If the net has Additional Broadcast enabled in its Edit form (e.g. for a segment like Amateur Radio Newsline), each date also shows a separate Broadcaster sign-up slot — a different operator can claim it, or one operator can click + Cover Both Roles to take both for that date. Whoever is signed up is shown, callsign and name, on the live check-in screen and the public /live page.

SCHEDULED NET REMINDERS

Enable Reminder Emails in a net's Edit form and set a lead time (in minutes) to have whoever's signed up as Net Control or Broadcaster on the Schedule tab emailed shortly before their net starts. Each role is reminded independently, at the email address they gave when signing up.

If nobody has signed up for a date, no reminder goes out — there's no one to email. This depends on the server having SMTP configured and a reminders cron job running; ask your administrator if you enable this and don't receive anything.

ARES/ACES MODE

Enable ARES/ACS Net in the net settings to activate evacuation zone tracking. An Evac Zone field appears in the check-in form — enter the station's zone (e.g. "Zone A") when they check in.

The zone is saved automatically to a per-net zone table. In future sessions, the station's last known zone appears as a 📍 badge in the Expected Stations list and is pre-filled when checking them in.

The Zone Roster panel shows all known zones grouped by zone name with their callsigns, sorted by callsign suffix. The Zone column also appears in the check-in table and the ICS-205 export.

ARES/ACES ACTIVATION MODE

For an actual activation — not a routine weekly net — check 🚨 ARES/ACES Activation on the ▶ Start New Session form (only offered for ARES/ACES nets). This switches that one session into tactical mode; leave it unchecked and the session works exactly like a normal net. Other sessions on the same net are unaffected either way.

Checking it reveals an Activation Schedule dropdown — pick a saved preset to pre-fill this session's tactical roster and Net Control rotation, or leave it at — None — to start empty. Saved schedules are managed ahead of time under the net's own edit form, in its 🚨 Activation Roster tab (ARES/ACES nets only): create as many named schedules as you want (e.g. "Full Activation", "Weather Watch"), each with its own tactical positions and NC rotation shifts, using the same forms described below. Applying one at session start copies it in — the saved schedule itself is untouched and ready to use again next time.

An activation session shows two tabs at the top of the screen: 📻 Check-In and 🗓 Station Schedule. Station Schedule is itself split into two sub-tabs: 🎯 Tactical Stations and 🎙 Net Control — Net Control hands off on its own rotation, separate from one-off field positions, so it gets its own planning surface (see below).

🎯 Tactical Stations is where you define one-off field positions for this activation — a tactical callsign (e.g. "SHELTER 1"), an optional location, an optional planned operator, and an optional Scheduled Sign-On (month, day, and time — defaults to today, and always this year, so there's rarely anything to change). Click ✏️ Edit on any position at any time to change its plan.

Check-In → TACTICAL ASSIGNMENTS (replaces the usual Expected Stations panel on an activation session) is where operators sign on and off tactical stations day-to-day. A vacant position shows Sign On — pre-filled with the planned operator if one was set, but fully editable if someone else shows up instead. An occupied position shows Sign Off & Replace (hand it to a new operator in one step) and Sign Off (vacate with nobody lined up yet). 🕐 History lists every operator who's held that position and when.

A vacant position past its Scheduled Sign-On time is flagged — ⏰ Due if it's still coming up today, ⏰ Due since once the time has passed.

The check-in roster on the right switches to Tactical / Callsign / Name for the duration of an activation session. A station that checks in without a tactical assignment shows its evacuation zone there instead, if one is on file.

NET CONTROL'S ROTATION SCHEDULE

On an activation session, 🎙 Net Control is created automatically the moment the session starts, and staffed right away by whoever's signed up for Net Control that day on the Schedule tab, or by whoever actually started the session if nobody had signed up. Its live status and controls live on Station Schedule → 🎙 Net Control (also mirrored on Check-In → Tactical Assignments).

Because Net Control classically rotates on a fixed cadence throughout a long activation, that sub-tab also has its own + Add Planned Shift form — queue up callsign, name, and a scheduled sign-on time for as many upcoming shifts as you want. They're listed chronologically, with the soonest marked NEXT UP.

When it's actually time to hand off, click 🔄 Hand Off Net Control — the incoming operator's callsign and name are auto-filled from the next planned shift, still fully editable in case of a last-minute change. Confirming closes the outgoing operator's shift and starts the incoming one immediately — reflected right away in the duty bar, the {{net_control}} variable in the Net Script, and the check-in roster, with the full handoff history under 🕐 History. The shift used for the auto-fill is removed from the queue once confirmed, whether or not you changed who actually signed on, so "next" always points at whoever's genuinely next.

Net Control can't be removed — an activation always has one — but it can be handed off, and its rotation replanned, as many times as the activation needs.

LOG A PAST NET

Sometimes a net forms quickly with no access to the web tool. Click 🕐 Log Past Net next to ▶ Start New Session to enter it after the fact — set the Date & Time of Net (month/day/time — always this year), and optionally who ran Net Control and, if the net carries one, the Broadcaster. Both default to whoever's scheduled or started the session for a normal session; for a logged one, set them directly since whoever's backfilling the log may not be who actually ran it.

Submitting drops you straight into a check-in screen for it. Every check-in you add is stamped with the reported date/time, not the moment you happened to type it in — that's the whole point of logging it after the fact. The screen shows Logged instead of Live/Ended and skips anything meant for running a net in real time — no clock, Expected Stations, Digital Voice Last Heard, or Net Script panel — but the check-in form, roster, and CSV/ICS-205 export all work exactly as normal. Re-typing a long paper roster one row at a time is tedious — click ⬆ Import CSV in the toolbar instead to add the whole thing at once (see Bulk Import from CSV above).

A logged session stays open to further check-ins until you click 🔒 Close Log — the same button that reads ■ End Session on a live one. Once closed, no more check-ins can be added; remove individual check-ins the usual way if you need to correct one before or after closing, or delete the whole session from the Sessions list to start over.

SESSION SUMMARY & ICS-205

When you end a session, a Session Summary card pops up showing total check-ins, session duration, traffic count, and new stations (first-time visitors to this net).

Click 📄 ICS-205 / Net Log to open a printable net log in a new tab. It includes the ICS-205 header (net name, frequency, NCS callsign, operational period) plus the full check-in roster and traffic message log. Use your browser's Print function to save as PDF.

You can also export the raw check-in data as a CSV for logging or upload to other systems.

SESSION HISTORY

The History view shows every callsign that has checked into the selected net, with check-in counts for the past 2 weeks, 4 weeks, and all time.

Use the filter dropdown to find: Last Net, Missed Last Net, Active (2 wks), Regular (4 wks, ≥2), Frequent (4 wks, ≥3), or Inactive (4 wks). Combine it with the text search box, a minimum check-in count, a last check-in date range, and — on ARES/ACES nets — a zone filter, for further narrowing.

Three report templates sit above the table: 📋 Roster (the full per-callsign table, the default), 📊 Summary Stats (aggregate cards — operators shown, combined check-ins, average per operator, sessions logged — plus a compact attendance table), and 🖨 Printable Report (a clean, print-ready layout with its own Print button). All three, and the ⬇ CSV export, reflect whatever filters are currently active.

CSV export has three column presets, picked from the dropdown next to the button: Full (everything, including License/State/Grid if already looked up), Minimal (Callsign, Name, Total Check-ins only), and License Detail (Callsign, Name, License Class, State, Grid).

PUBLIC NET DIRECTORY

Enable List in Public Net Directory in a net's Edit form to show it at your organization's /directory/<org> page — public, no login required, separate from the real-time /live/<org> check-in view. Listed nets show their name, net type, frequency, description, weekly schedule, and your callsign as the host.

Nets are unlisted by default — opt in per net. Visiting /directory or /live with no organization in the URL shows a picker listing every organization that has at least one publicly listed net.

NET REPOSITORY

Net Repository is a separate, community-run central directory — a net listed in your own Public Net Directory (above) can also be pushed there so it's discoverable beyond this one instance. It's entirely optional and off by default.

ONE-TIME SETUP

1. Set NET_REPOSITORY_URL in .env to the Net Repository instance you want to publish to (ask its admin for the URL, or run your own from the repo linked above), then restart the app.

2. In Admin → Net Repository, fill in a name (shown to that instance's admin for review) and click Request API Key.

3. This enters that instance's moderation queue. Click Check Status any time afterward — once approved, the key is stored automatically. No .env edit or restart needed. Use Forget This Key to clear it and start over.

From then on, checking List in Public Net Directory on any net's Edit form pushes it — every save, not just the first, so schedule changes and edits stay in sync automatically. Optional fields on the same form (Band, Mode, CTCSS Tone, Region, State, Website) make the listing more useful; Website falls back to the org-wide one in Admin → Branding if left blank.

Already had public nets before setting this up? python3 push_to_net_repository.py backfills every currently-public net in one shot — safe to re-run, existing listings get refreshed rather than duplicated.

ADMIN PANEL

The very first user to ever register on an instance automatically becomes Super Admin — sees and manages every organization, and is the only registration that skips approval entirely (there's no one else to ask). Every other new registration either founds its own organization — pending a Super Admin's approval, shown in their Admin panel's Pending Approval list — or requests to join an existing one, which needs approval from that organization's own admin instead.

An organization admin gets a scoped Admin page — approve/reject pending members of their own organization only (this does not cover approving a brand-new organization's founder, which only a Super Admin can do). A Super Admin's Admin page is unchanged: approve/deactivate any account, grant Super Admin, delete accounts, and opt in to email notifications for new registrations using the ✉/📧 toggle in the Notify column.

Newly approved operators receive an automatic confirmation email if SMTP is configured in .env.

DATABASE MIGRATIONS

Schema migrations are managed by migrate.py in the app directory. It is safe to re-run at any time — every step uses IF NOT EXISTS. ./deploy.sh now runs it automatically as part of every deploy, before the service restarts — no manual step needed if you use it.

To run it by hand:

sudo -u netcontrol python3 /opt/netcontrol/migrate.py

Fresh installs: new tables are created automatically on first startup — no migration needed. Run migrate.py only when upgrading an existing instance after a code update.

GMRS licence database

Seed the local GMRS callsign database on first install, then let the daily cron keep it current:

# Initial seed (full ~54 MB download)
python3 /opt/netcontrol/gmrs_sync.py --mode full

# Routine update (runs automatically via cron — daily transaction file)
python3 /opt/netcontrol/gmrs_sync.py --mode update

Scheduled net reminders

Net owners enable reminders per-net in the Edit form, but sending them requires send_reminders.py running frequently via cron (it's idempotent, safe to run every few minutes):

*/5 * * * *  /opt/netcontrol/venv/bin/python3 /opt/netcontrol/send_reminders.py >> /var/log/nettracker/reminders.log 2>&1

DATABASE STATS (SLOW QUERIES)

Admin → DB Stats (Postgres only — hidden/no-op on SQLite) shows database size, connection counts, and largest tables with no setup. The Slowest Queries panel additionally needs the pg_stat_statements extension enabled on the Postgres server — a one-time, superuser-level step outside the app, not something migrate.py can do.

Self-managed Postgres (Ubuntu/Debian):

# 1. Add it to shared_preload_libraries (find your config file with
#    `sudo -u postgres psql -c "SHOW config_file"` if this path is different)
sudo nano /etc/postgresql/*/main/postgresql.conf
#   shared_preload_libraries = 'pg_stat_statements'

# 2. Restart Postgres -- a reload isn't enough, shared_preload_libraries
#    only takes effect at startup
sudo systemctl restart postgresql

# 3. Enable the extension in this app's own database (once)
sudo -u postgres psql -d ham_net_tracker -c "CREATE EXTENSION pg_stat_statements;"

Use your real database name from DATABASE_URL in .env if it isn't ham_net_tracker. On managed/cloud Postgres (RDS, DigitalOcean, Cloud SQL, etc.) postgresql.conf usually can't be edited directly — enable the extension via your provider's parameter group / extension allow-list instead, then still run the CREATE EXTENSION step above. No app restart or migration needed either way — the panel reads live once it's enabled.

UI TRANSLATION (ARGOS TRANSLATE)

Optional, off by default. Translates the app's own UI using Argos Translate, an offline neural machine translation library — no third-party API, nothing leaves the server. It's a genuinely heavy dependency (pulls in a real ML stack), so it's opt-in and documented separately in the README rather than something every install picks up by default.

Set TRANSLATION_ENABLED=true in .env and install the optional argostranslate package, then use Admin → Languages to enable any language it supports — this downloads that language's model and pre-translates the app's known strings in the background (Pending → Installing → Ready). Full setup steps are in the README's "UI Translation" section.

A visitor's browser language is auto-detected and applied automatically on first visit, but only from languages an admin has already enabled — nothing is translated into a language nobody turned on. A "🌐 via Argos Translate" credit appears next to the language switcher whenever a translated language is active, since machine translation isn't perfect (especially for ham-radio-specific terms).
