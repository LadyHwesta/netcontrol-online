## Low Priority

### UI translation (argos-translate) covers everything except the Changelog/Guide prose, directory.html, and public.html
The translation framework itself (`routers/translation.py`, `static/js/i18n.js`, the admin Languages tab, `extract_i18n_strings.py`) is complete and works end-to-end. Coverage was extended incrementally, one real-estate slice at a time: the auth/login screen and shared sidebar nav, the Nets view, Sessions/Schedule, `checkins.js` in full (added `tn(n, singular, plural)` to `i18n.js` for count-based text along the way — see its own doc comment for the "English one/other split only, not full per-language plural rules" limitation), the whole Admin page, the History view + DMR/APRS dynamic rendering, and finally Account (`tokens.html`/`tokens.js`), Report/Request (`report.html`/`report.js`), and Help's navigational chrome (2026-08-31: Guide/Changelog tabs, the "what are you looking for?" index, Guide sub-tabs, every section heading). Two things were deliberately left out of that last slice, not missed:

- **`help.html`'s Changelog entries and each Guide section's full prose body** — only the headings/navigation are wrapped. The changelog specifically is a historical record that grows with every shipped feature (every entry ever written, forever) — machine-translating that whole and ever-growing corpus isn't a good use of the pre-translation budget the way live, current-facing UI is. Revisit only if a real non-English-speaking user asks for it specifically; headings alone already make the page navigable.
- **`directory.html`/`public.html`** don't even load the shared JS helper files (`state.js`/`utils.js`/`i18n.js`) — they're self-contained pages with their own inline scripts. Wiring in translation there is a separate, smaller effort (they got the pre-paint `<html lang>` script as part of this work, but not `t()`/the switcher). `aprs-map.js` is a partial exception: it's shared with `public.html`, so it now uses a local `_t = typeof t === 'function' ? t : (s => s)` fallback alias rather than a bare `t()` — worth copying that pattern if any other shared module needs to work on a page without `i18n.js`.
- When wrapping a lookup table in `t()` (badge-status maps, etc.), build it inside the render function rather than as a module-level `const` — a module-level object literal is evaluated once at script load, before any language is even selected, and its `t()`-translated values would stay frozen at whatever `currentLang` was then. Hit this once already (`admin.js`'s `LANG_STATUS_BADGE`, fixed by turning it into a function called fresh on every render) — worth grepping for `^const.*t(` before calling coverage of a file complete.
- Server-side error messages returned from API calls (e.g. `toast(e.message, 'error')` where `e.message` is the raw response body) are **not** translated — only the client-side UI-chrome strings around them are. Translating validation/error responses would mean routing them through `translate_cached` on the backend, a separate piece of work.
- Re-run `python3 extract_i18n_strings.py` after each batch of new `t()`/`tn()`/`data-i18n` call sites, so an admin's "enable a language" bulk pre-translate stays comprehensive.

- ~~SQLAlchemy is used synchronously~~ — full migration to async SQLAlchemy (`create_async_engine`/`AsyncSession`) + `asyncpg` in production, `aiosqlite` in tests. `database.py` auto-rewrites a plain `postgresql://`/`sqlite://` `DATABASE_URL` to `+asyncpg`/`+aiosqlite`, so existing `.env` files need no change. All 148 route handlers in `main.py` are now `async def`; all 179 `db.query(...)` call sites converted to SQLAlchemy 2.0 `select()`/`db.execute()`; all 29 internal helper functions taking a session are now async and properly awaited at every call site. `net_repository.py`, `send_reminders.py`, `push_to_net_repository.py`, and `demo_reset.py` converted too (they share the same engine — an in-memory test DB is per-connection, so a second sync engine would've been invisible to the async one in tests); `migrate.py`/`gmrs_sync.py` (raw `psycopg2`, no ORM) and `dmr_relay.py`/`aprs_relay.py` (pure HTTP clients) needed no changes. `tests/conftest.py` moved off `sqlite:///:memory:`+`StaticPool` to a temp file-based SQLite DB — verified via a standalone repro that the in-memory+StaticPool combination hangs indefinitely once `TestClient` is involved (it drives the ASGI app from a separate thread/event loop via an `anyio` blocking portal, so a single `aiosqlite` connection shared via `StaticPool` ends up driven from two event loops at once, which deadlocks); a file needs no `StaticPool` since it's naturally shared across connections. `pytest-asyncio` added (`asyncio_mode = auto`, `asyncio_default_fixture_loop_scope = session` — the session scope is required for session-scoped async autouse fixtures to work with plain sync test functions at all). Found and fixed along the way: `AsyncSession.delete()` is itself a coroutine (unlike `.add()`, which stays sync) — every call site needed `await`; a couple of `await helper(...).attr` call sites had an operator-precedence bug (needed `(await helper(...)).attr`); one `.first()`→`scalar_one_or_none()` auto-conversion (`_is_first_checkin_for_net`) needed to go back to take-the-first semantics instead, since GMRS nets legitimately allow multiple check-in rows for the same callsign. Full 503-test suite passes; live-verified against a real `uvicorn` + `aiosqlite` file DB (register → login → create net → session → check-in → stats → end session → delete net, zero errors/warnings in the server log) (2026-08-30)
- ~~Single-file backend (`main.py`)~~ — split the ~5,800-line, ~150-route-handler `main.py` into a `routers/` package: 17 domain modules (`auth`, `orgs`, `nets`, `sessions`, `checkins`, `tactical`, `evac_zones`, `expected_stations`, `traffic`, `history`, `callsign_lookup`, `schedules`, `digital_voice`, `aprs`, `admin`, `public`, `support`) wired up via `app.include_router(...)`, plus `routers/deps.py` (auth/db/rate-limit dependencies), `routers/schemas.py` (the handful of Pydantic models genuinely shared across 2+ routers — `UserOut`, `AdminUserOut`, `OrganizationOut`, `NetOut`, `CheckinOut`), and `routers/helpers.py` (shared non-auth helpers — email/SMTP, CAPTCHA verification, the generic settings store, org bootstrap, and the net/session access-control helpers like `_get_editable_net`/`_get_session_for_user`). `main.py` itself shrank to ~215 lines: logging config, app/lifespan/middleware/static-mount assembly, the 17 `include_router` calls, and the handful of frontend/SPA-shell routes that don't belong to any one domain. Two real cross-section couplings the split surfaced got fixed outright rather than left as awkward cross-router imports: the checkin traffic-toggle endpoints, previously defined under the "Evacuation Zone routes" banner despite being checkin endpoints, moved into `checkins.py`; and Net Schedules + Net Control Signups (which shared `SignupCreate`/`SignupOut`/`DAYS`/`_signup_to_out`) were merged into one `schedules.py` instead of split. The bigger discovery: a wide swath of the test suite controls app behavior via `monkeypatch.setattr(main, "SOME_CONSTANT_OR_FUNCTION", ...)` — SMTP config, CAPTCHA config, `_verify_turnstile`/`_verify_recaptcha`, `send_email` itself. Since a Python function resolves module-level names from `__globals__` at call time (the module it's *defined* in, not wherever it's imported from), moving that code out of `main.py` silently broke every one of those patches — the fixture would still patch a name, just not the one any code path actually read anymore. Fixed by (1) retargeting `tests/conftest.py`'s fixtures and a handful of test files (`test_captcha.py`, `test_email_send.py`, `test_support.py`, `test_aprs.py`, `test_dmr.py`) to patch `routers.helpers`/`routers.<domain>` directly instead of `main`, and (2) for `send_email` specifically — called from many different router modules, not just one helpers-internal function — switching every caller to qualified `helpers.send_email(...)` access (`from routers import helpers`) rather than a bare `from routers.helpers import send_email`, so one patch at the real definition site is observed everywhere regardless of which router the call originates from. All 515 tests pass unchanged in substance (only their patch targets moved); live-verified against a real `uvicorn` process — register → login → create net → session → check-in → history → APRS/DMR config, plus every frontend/public page — with zero duplicate route registrations across the 139 registered routes (2026-08-30)
- ~~In-memory cache and rate limiter won't survive multiple workers~~ — `slowapi`'s rate limiter (`routers/deps.py`) now takes `storage_uri=REDIS_URL` (unset by default, so `limits` falls back to its own in-memory `MemoryStorage` exactly as before — verified live that `redis://...` resolves to `RedisStorage` and an unset `REDIS_URL` still resolves to `MemoryStorage`). The DMR/APRS relay-push caches (`routers/digital_voice.py`/`routers/aprs.py`) gain a third tier ahead of their existing in-memory-dict + `SystemSetting` fallback: a shared `_redis_cache_read`/`_redis_cache_write` pair in `routers/helpers.py`, consulted first on read and always written on write when `REDIS_URL` is set, entirely additive (a no-op with it unset, so single-worker behavior is byte-for-byte unchanged — the existing dict+DB fallback stays in place underneath for exactly that case, and as Redis's own outage fallback). `WORKERS` added to `.env`/`.env.example`/the systemd unit template (`--workers ${WORKERS}`, default `1`) — no implicit default the way a shell script could give it, so always spelled out explicitly. `redis` added to `requirements.txt` (optional, lazily imported only when `REDIS_URL` is actually set, same pattern as `argostranslate`/`altcha`). New `tests/test_redis_cache.py` (9 tests) using a fake in-process Redis stand-in rather than a real server (Redis stays optional; CI has none running) — round-trip, missing-key, and outage-graceful-degradation on the shared helper, plus the actual cross-worker correctness property for both caches (a "different worker," simulated by clearing the in-memory dict, still sees a fresh push via Redis rather than only the DB fallback). Live-verified separately against a real disposable Redis instance: cache round-trip, the cross-worker DMR scenario end-to-end against a real DB, and the rate limiter's storage backend resolution — none of that re-proven in the committed test suite, since it's third-party library behavior, not app logic. New README "Running with multiple workers" section; `WORKERS > 1` without `REDIS_URL` isn't blocked (a worker process has no reliable way to detect its own sibling count), just documented as the operator's responsibility to pair correctly (2026-09-01)
